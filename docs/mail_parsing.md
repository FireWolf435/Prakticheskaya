# Правила разбора входящего письма (ПМ.02, п. 5.1.4)

## Общие принципы

Письмо на `support@corp.local` создаёт заявку. Ответ на письмо с `[#номер]` в теме добавляет комментарий к существующей заявке. При смене статуса отправляется уведомление по email.

## Заголовки, которые проверяются

### 1. Автоответы
- `Auto-Submitted: auto-replied` или `auto-generated`
- `X-Autoreply: yes/true/1`
- Тема начинается с «Автоматический ответ»

**Действие:** Письмо пропускается (не создаёт заявку и не добавляет комментарий).

### 2. Системные письма
- `From: mailer-daemon@...`
- `From: no-reply@...` или `noreply@...`
- `Return-Path: <>`

**Действие:** Письмо пропускается.

### 3. Фишинг
- `Received-SPF: fail` (отправитель IP не совпадает)
- Поддельный `Return-Path` (не содержит `@corp.local`)

**Действие:** Письмо отклоняется (заявка не создаётся).

### 4. Опасные вложения
- Исполняемые файлы (`.exe`, `.scr`, `.bat`, `.cmd`, `.com`, `.pif`, `.js`, `.vbs`, `.ps1`, `.jar`, `.msi`)
- PE-сигнатура (`MZ` в начале файла)

**Действие:** Вложение изолируется в карантин, к заявке не прикрепляется.

## Разбор письма

### Извлечение полей

| Поле | Источник | Обработка |
|---|---|---|
| `from_name` | `From` | RFC 2047 декодирование |
| `from_email` | `From` | `email.utils.parseaddr` |
| `subject` | `Subject` | RFC 2047 декодирование, нормализация пробелов |
| `date` | `Date` | `email.utils.parsedate_to_datetime` |
| `message_id` | `Message-ID` | Извлечение ID |
| `return_path` | `Return-Path` | Проверка на `<>` |
| `spf` | `Received-SPF` | Проверка на `fail` |
| `auto_submitted` | `Auto-Submitted` | Проверка на `auto-replied` |
| `x_autoreply` | `X-Autoreply` | Проверка на `yes/true/1` |
| `body` | `text/plain` | Извлечение текста, удаление цитат (`>`) |
| `attachments` | `attachment` parts | Сохранение безопасных, карантин опасных |

### Определение категории

Ключевые слова в теме + тексте письма:

| Категория | Ключевые слова |
|---|---|
| Информационная безопасность | фишинг, вирус, подозрительн, мошен, взлом, угроза, спам |
| Телефония | телефон, ip-телефон, звонк, гарнитур, гудк |
| Печать | принтер, печата, картридж, мфу, сканер, зажёвыва, бумаг |
| 1С | 1с, 1c, проведени, бухгалтер |
| Электронная почта | outlook, почт, письм, ящик, переадрес, рассылк |
| Сеть и интернет | сетев, сеть, интернет, сайт, wi-fi, wifi, лвс |
| Серверы и сервисы | сервер, файлов, файл, сервис |
| Учётные записи и доступ | доступ, парол, учётн, учетн, разблокиров, верните |
| Компьютеры и периферия | компьютер, пк, флешк, usb, монитор, клавиатур, мыш, периферия, ноутбук, не включается |
| Прикладное ПО | программ, софт, установк, приложени, обновлен |

### Определение приоритета

- Если текст содержит признаки срочности («очень срочно», «срочно», «asap», «горит», «!!») → приоритет 2 (Высокий)
- Иначе → приоритет 3 (Средний)

### Маскирование секретов

Пароли и логины в тексте письма маскируются:
- `пароль: secret123` → `пароль: ***`
- `login: admin` → `login: ***`

### Обработка вложений

1. **Безопасные вложения** (не исполняемые) → сохраняются в `mailintake/attachments/`, прикрепляются к заявке
2. **Опасные вложения** (исполняемые) → изолируются в `mailintake/quarantine/`, к заявке не прикрепляются

### Идемпотентность

Перед обработкой удаляются следы предыдущего запуска:
- Заявки с номером `SD-2026-*` (создаются только этим модулем)
- Комментарии с `source='mailintake'`
- Строки журнала `stage.mail_intake_log`

Заявки легаси-системы (числовые номера) и комментарии других источников не затрагиваются.

### Дубликаты

Повторное письмо от того же автора с той же темой отклоняется как дубликат.

### Уволенный отправитель

Если отправитель уволен (is_active = false, dismissal_date установлена), заявка на доступ не создаётся (требование ИБ).
