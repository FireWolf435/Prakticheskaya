# Service Desk — система учёта и обработки заявок технической поддержки

Информационная система технической поддержки (Service Desk) для ООО «Вектор-Пром»:
приём и обработка заявок, учёт оборудования, каталог пользователей (LDAP) и
почтовая интеграция.

Проект выполняется в рамках двух производственных практик:

- **ПМ.11** «Разработка, администрирование и защита баз данных» — ядро: БД,
  её администрирование и защита;
- **ПМ.02** «Осуществление интеграции программных модулей» — программные модули
  на Python вокруг ядра, их интеграция и тестирование.

> Тема: «Разработка защищённой информационной системы учёта и обработки заявок
> технической поддержки (Service Desk) с централизованным каталогом пользователей
> и почтовой интеграцией».

## Стек

| Технология | Назначение |
|---|---|
| PostgreSQL 16+ | данные, бизнес-правила, безопасность |
| Python 3.12+ | доменная логика, модули интеграции |
| Docker Compose | развёртывание всего стенда одной командой |
| OpenLDAP | централизованный каталог пользователей |
| docker-mailserver | почтовый сервер (Postfix + Dovecot) |

## Быстрый старт

Требуется установленный **Docker Desktop**.

```bash
# 1. Скопировать шаблон переменных окружения
cp .env.example .env

# 2. Заполнить .env своими паролями (файл НЕ коммитится в git)

# 3. Поднять весь стенд
docker compose up -d
```

После запуска поднимаются три контейнера:

| Контейнер | Сервис | Порт |
|---|---|---|
| `sd-postgres` | PostgreSQL | 5432 |
| `sd-ldap` | OpenLDAP | 389, 636 |
| `sd-mail` | docker-mailserver | 25, 143, 587, 993 |

Схема БД (`ref`, `core`, `audit`, `sec`, `stage`) создаётся автоматически при
первом старте `postgres` из скриптов `db/init/*.sql`.

## Работа с исходными данными (раздел 3 ТЗ)

Данные выдаются архивом (выгрузки из кадровой системы, 1С, старой системы
заявок, LDAP и почтового ящика `support@`). Данные намеренно не очищены —
поиск и устранение аномалий являются частью задания.

**Загрузка в схему `stage` (пункт 3.1):**

```bash
python -m pip install -r requirements.txt
python importer/load_stage.py [путь_к_папке_с_данными]
```

Загрузчик кладёт каждый файл «как есть»: одна исходная строка = одна строка
`stage`, плюс служебные столбцы `src_line` (номер строки) и `src_file` (имя
файла). Загрузка **идемпотентна** — повторный запуск не создаёт дублей.
Путь к данным также можно задать переменной окружения `SD_DATA_DIR`.

**Обработка входящей почты (пункт 3.6):**

```bash
python importer/transform.py     # сначала заявки легаси-системы
python mailintake/intake.py      # затем письма support@ -> заявки/комментарии
```

Модуль `mailintake` разбирает письма `mail/*.eml` (заголовки, кодировки,
вложения, автоответы) и по каждому фиксирует результат и причину в журнале
`stage.mail_intake_log`; итог — отчёт `docs/mail_report.txt`. Запуск
идемпотентен: повторный не создаёт дублей. Создаваемые из почты заявки
получают номера `SD-2026-NNNN`.

## Требования к БД (ПМ.11)

- 18+ таблиц в схемах `ref`, `core`, `audit`, `sec`, `stage`;
- пользовательские домены: `email` (citext), `snils` (с проверкой контрольной
  суммы), `inv_no`;
- `EXCLUDE USING gist` по `tstzrange` для графика дежурств (границы `[)`);
- частичный уникальный индекс: один СНИЛС — один действующий трудовой период;
- 7+ функций/процедур: `calc_sla_deadline`, `calc_sla_spent`,
  `change_ticket_status`, `auto_assign`, `reopen_ticket`, `move_asset`,
  `sec.register_user`, отчётная табличная функция;
- 6+ триггеров: аудит изменений, запрет переходов статусов, пауза SLA,
  outbox + `pg_notify`, `updated_at`/версия строки, событийный триггер DDL;
- 12+ запросов: оконные функции, `WITH RECURSIVE`, `LATERAL`/`FILTER`/
  `GROUPING SETS`/`ROLLUP`, полнотекстовый поиск;
- RLS, `pgcrypto`, три docker-сети, `pg_hba.conf`, SSL, клиентский сертификат
  для роли `dba`.
